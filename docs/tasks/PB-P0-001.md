# PB-P0-001 — Minimum TypeScript/Fastify Scaffold

**Status:** PROPOSED — requires approved Repository Foundation PR and explicit task kickoff. No implementation is implied.

**Scope authority:** `../PRD.md` section 2/3, P0 section 9; `../ARCHITECTURE.md`.

## Objective

Create a minimal reproducible strict TypeScript/Fastify application baseline suitable for adding PostBro product integrations. This is NOT the application feature release.

## In scope

- Node.js >=22 project with lockfile, strict tsconfig, sensible package scripts (`dev`, `build`, `typecheck`, `lint`, `test` as implemented).
- Minimal Fastify composition with GET `/health` responding with stable health status and no environment secrets.
- Central typed configuration validation reading variables needed for this slice only. `.env.example` stays placeholders, no real credentials, and app must not require Meta/Supabase keys to run bare health endpoint.
- One or more automated tests for health and configuration errors. CI workflow that runs actual installed scripts against the locked deps and fails on test/type errors.
- Document the exact setup/test/build commands and required Node version. Small reviewable Docker scaffold only if it does not distract from this task; prefer defer deployment to a scoped follow-up.

## Out of scope

- OAuth, real Meta API calls, Telegram product bot creation, publishing, schedules, Supabase DB access, persona import, UI, live sends, new infra, DNS/TLS, production deployment.

## Acceptance checks

1. Clean checkout with supported Node can install exact locked dependencies and run commands documented in README.
2. TypeScript strict compilation and unit tests pass; include concrete command/exit results and CI URL if CI actually executes.
3. GET `/health` returns success in a controlled local test; unknown route behaves predictably.
4. No app secrets required/printed and no private .env tracked.
5. No live external service side effects; no unrelated files/modules added.
